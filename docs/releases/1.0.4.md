# Candidate release 1.0.4

This patch repairs the WordPress archive caller after the 1.0.3 tag workflow
failed at startup because it could not grant the shared workflow's attestation
job the required permissions. The grant is confined to the archive caller;
artifact attestation stays explicitly disabled. All shared workflow references
use the immutable Workflows 1.2.2 commit
`cd809f3986df3ea617d2d26bdf21ab69cae19c1e`.

WordPress artifacts exclude tests, documentation, QA configuration and local
review files while retaining the profiler's runtime code and bundled resources.
The plugin header identifies this patch as 1.0.4. The private profile storage and
custom authentication-cookie masking published in 1.0.3 are unchanged.

The archive also retains the default WordPress Plugin Check standard. Templates
use explicit PHP echo syntax with unchanged rendered output. Narrow inline
exceptions document native URL parsing in standalone profiler contexts, native
permission diagnostics, safely encoded timeline JavaScript and gated read-only
request/SQL diagnostics. No archive sniff or required check is disabled globally.

This is a prepared candidate. Publication requires exact-commit hosted checks
and a fresh tag archive check; the historical 1.0.3 tag remains unchanged.
